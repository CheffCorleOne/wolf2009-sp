# Пересмотр работы: 2026-11-04

Аудит метода завершён. По прямой просьбе владельца 2026-11-04 реализация
возобновлена: Gemini пишет код, Codex проверяет и интегрирует.
Последний опубликованный и проверенный checkpoint — `b72c4bf`. Изменения
после него являются незавершённой локальной работой, а не новым релизом.

## Вывод по архитектуре

Расширение закреплённого GPL idTech4A++ остаётся рабочей гипотезой: имеются
подтверждённые native filesystem/render/game/physics пути. Переписывание всей
основы на другом языке или механический перевод всей DLL не дают готовой
переносимой кампании. Но компонентные декодеры и проверки сами по себе также
не приближают к игре, если их не соединять в последовательные игровые сценарии.

Следующий результат должен быть одним законченным сценарием: обычный запуск
карты создаёт исходного игрока; пользователь ходит, приседает, получает MP40,
стреляет, перезаряжается; нативная цель получает урон. Затем тот же путь
подключается к исходному старту trainyard, его сущностям и событиям. Исходный
trainyard начинает с weapon_none; тестовая выдача MP40 — отдельная операция.

## Фактическое состояние незавершённых изменений

- Применён сохранённый MP40 root-LOD profile3. Его прежние portable проверки
  сохранены; нового native/GPU результата MP40 пока нет.
- Подготовлен общий wide-TRM ABI64/160/96 и multiword CM caches. Старый save
  wire32/33/16 сохраняется; wide trace отказывает до записи своего record.
- Portable SourcePlayerHull: 3/3 CTest PASS, включая исходные stand/crouch
  supports. Native collision probe написан/скомпилирован отдельно, но не запущен.
- Portable SourcePlayerProfile: 2/2 CTest PASS. Source map loadout отделён от
  armed defaults. Исходные HKXS stand/crouch формы декодируются без capsule
  fallback. Native source idPlayer, lifecycle hooks и проверки написаны.
- Portable SourceWeaponProfile/controller: 2/2 CTest PASS. Native owner-aware
  MP40 controller и ray/Damage проверки написаны. Renderer/view binding не готов.
- Добавлен explicit SourceSession descriptor и core fixture для обычного
  devmap. Game-side проверки/runner flags ещё не подключены полностью.
- Добавлен строгий Player single-sample sound profile по исследованному reload
  SFX. Это незавершённое изменение: новых portable/native audio проверок нет.
- Android x86_64 core `doom3` собрался (240 steps, exit0). **Game module после
  изменения wide-TRM ABI ещё не собран. Пару старого libgame.so и нового core
  запускать нельзя.** Нового APK и нового runtime-прохождения не было.

## Обнаруженные незакрытые риски

1. Stock NextWeapon/PrevWeapon могут зациклиться: source inventory mask содержит
   исходные slots, а native Doom def_weapon отсутствуют. Нужна source dispatch
   или ограниченный guard; проверить Select/NextBest/Drop вместе с этим.
2. Ошибочный повторный BeginSourceSession сейчас очищает прежний active session
   в catch. Нужна транзакционная обработка повторного входа.
3. Требуются сборка libgame.so, согласованная ABI-пара и фактический запуск
   player/weapon/native collision QA. Синтаксические проверки этого не заменяют.
4. MP40 commands должны иметь одного владельца. WeaponAttack обслуживает
   controller; reload POI/eye/sound требуют явной presentation policy.
5. Кампания не реализована: map ENTS dispatch, большинство BRAI действий,
   противники/AI/navigation, Veil, mission progression и saves остаются впереди.

## Распределение работы

Gemini получает ограниченные задачи в отдельной копии: исправления конкретных
подсистем и интеграцию до явно заданного результата. Один агент владеет одним
набором файлов. Codex сохраняет архитектурные решения, проверку binary/runtime
свидетельств, review diff и приёмку поведения. Публикация — только после проверки.
Массовый запуск Codex subagents по умолчанию прекращён. Не дублировать одни и те
же исследования и полные тесты без нового риска или изменений.

Первая задача Gemini — независимый аудит этой рабочей версии относительно
`b72c4bf`: критический путь к играемому сценарию, ошибки интеграции, план малых
следующих изменений. До результата аудита новый engine code не писать.
Процент экономии лимита и срок полной кампании заранее не обещаются.

## Результат пилота Antigravity/Gemini

Независимый аудит выполнен Gemini в отдельном worktree на локальном WIP
snapshot `6d747fd`. Codex проверил существенные замечания по фактическому C++
и вернул недоказанные выводы на исправление. Итоговый локальный отчёт сохранён
в `evidence/orchestration/gemini-strategy-audit-reviewed.md`; коммерческие
данные для этого аудита не передавались. Engine source в worktree — только
отдельные GPL reference files. Аудитор не менял tracked implementation files,
не собирал и не запускал WIP. Все агенты после аудита остановлены.

Подтверждены статическим разбором: отсутствие выхода из stock weapon-cycle
при source mask без Doom definitions; разрушение active session при ошибочном
повторном Begin; отсутствие новых game-side QA entrypoints. Это замечания к
незавершённой интеграции, не результаты нового runtime и не регрессии b72c4bf.
Stock idWeapon при этом создаётся: прежнее объяснение через неизбежный null
исправлено. Стартовый weapon_none остаётся намеренным исходным loadout.

Новая последовательность работы после возобновления:

1. Gemini завершает безопасную интеграцию source player/session/weapon input
   и wiring native QA одним ограниченным изменением. Codex проверяет diff,
   согласованную ABI-пару и фактические movement/ammo/damage/teardown checks.
2. Gemini подключает видимый MP40 к тому же пути: оригинальные mesh/rig/текстуры,
   idle/fire/reload и один владелец frame commands. Проверка включает кадр и
   пользовательский ввод. Это отдельный критерий после headless интеграции.
3. Затем — source trainyard ENTS/миссионные события/противники в том же игровом
   цикле. Не возвращаться к новым изолированным props вместо этого сценария.

Архитектура остаётся рабочей гипотезой, а не доказанным единственным или самым
быстрым решением. Первое доказательство эффективности нового процесса —
принятый native игровой сценарий. Владелец возобновил работу после аудита;
сначала заканчивается игрок и MP40, затем кампания.
