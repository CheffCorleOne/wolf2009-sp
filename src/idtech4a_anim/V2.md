# Native named source animation v2

V2 connects the named HKXA reader, checked spline codec and explicit caller
rig to ordinary `idMD5Anim`, `idAnimator` and SourceVisual entities. It accepts
mesh-v2 models independently of a particular clip. V1 wire/aliases and its
qualified greeter sampler retain their existing behavior.

```cpp
bool Wolf2009_RegisterSourceAnimationV2(const char* nativeMeshAlias,
    const char* hkxaPath, const char* animationSkelPath,
    const char* exactClipName, const char* exactAnimationSkeletonName,
    int explicitRigProfile, idStr& animationAlias);
```

Profile `1` is ordinary visual full-local-pose replacement: explicit caller
skeleton, no packet binding table, tracks==bones, identity curve scale. Every
model joint name and parent must match in order. Count equality does not select
a rig. Partial/remapped/additive/scaled, float/face, event and root-extraction
profiles are unavailable. The modelDef and SourceVisual factories accept the
resulting alias; original actor classnames and ENTS `frame` are not translated.

| Source role | Metadata | Payload sent through API8 |
| --- | --- | --- |
| Model | MODL path, epoch, byte count/FNV | None |
| Mesh skeleton | SKEL path/name, epoch, byte count/FNV | None |
| Animation | HKXA path/clip name, epoch, byte count/FNV | Original HKXA |
| Animation skeleton | SKEL path/name, epoch, byte count/FNV | Original SKEL |

Both skeleton names can differ. Reference poses, MODL bind transforms and
animation curves retain distinct roles. The core verifies the resident mesh
request and all four source identities, decodes the clip and checks the named
hierarchy. The game verifies the readonly capability's wire/key, received
payloads, decoded rig/timing and actual model alias/hierarchy. Geometry source
qualification remains with the core producer. Private core/STL layouts do not
cross the API8 boundary.

Alias: `wolf2009/_animation/anim/v2/<key>.md5anim`. The complete key includes
all four identities, both skeleton names, clip/model names, geometry/LOD
policies, requested slot, counts and source timing. Metadata is capped at
64 KiB, strings at 4096 bytes and each original payload at 64 MiB. Unknown
versions/policies, inconsistent roles, lengths, fingerprints and trailing
bytes are refused. FNV is a local identity; registry collisions compare full
metadata. V1 and V2 use separate codecs and registries.

An opened readonly `idFile` owns its bytes, request and deduplicated mount
leases independently of registry discovery. Shared labels require consistent
epochs. Scoped removal does not invalidate an open file. Open/reload revalidate
the current sources and model; reload accepts only unchanged full metadata.
Remounting any role requires fresh aliases. Definitions/models/unused cached
animations must release their refs before source unmount; pins are not forced.

Timed sampling uses source seconds directly. Frame sampling selects block/local
frame directly; `ConvertTimeToFrame` obtains a block-aware coordinate. No
integer FPS is inferred. Float32 source timing and shared endpoints mean these
coordinate helpers are not pose-preserving inverses. Native duration ends at
`ceil(duration*1000)` milliseconds with one final clamped-pose update. V2
runtime codec/FK exceptions become native game errors, preserving the module
boundary instead of silently skipping bad pose data.

Actual Android15 x86_64 validation passed five game probes: body182/41/335,
including two blocks; a shared-mount body case; and a 24-frame/two-bone locker.
There were 270199 game checks, 78 pose comparisons, 83 native snapshots and
1622 normal game frames; maximum joint error `1.526e-5`, bounds error zero.
Checks cover direct time/frame sampling, block edges, independent instances,
crossfade, actual bounds, endpoint, reload, refusals and SourceVisual lifecycle.
Core: 711 checks, 25 descriptor reads, eight refusals, four independent epoch
cases and distinct/shared mounts. Removing registration while a file remained
open preserved all four leases. Normal shutdown returned descriptor count to
zero. V1's 179663 checks also passed in the same process.

The original locker has 2 joints, 163 vertices and 112 triangles. Its exact
model/SKEL come from literal source declarations. Its explicit no-LOD-record
profile uses compatibility slot0; it does not invent authored LOD0. Searchable
gameplay is not implemented. Separate native GLES body proofs still use
supplied poses; these probes establish CPU/game/render-world behavior rather
than entity-driven GPU rendering or campaign completion.

Build/test: `-WithAnimationV2Checks` plus the owner's `RendererGameRoot`.
Production: `-WithWolfAnimation`, without QA. APK packaging is not required.
Patch18 adds the narrow native frame-coordinate hook; legacy engine sources
remain C++98, private adapters C++11. Original resources and run outputs are
excluded from the source release.
